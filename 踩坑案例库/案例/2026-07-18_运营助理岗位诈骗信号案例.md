# 运营助理岗位 · 诈骗/灰产信号案例样板（已脱敏）

公开仓库只保留**手法与规则**，不写真实招聘主体、发薪主体、平台链接或转账截图。

## 基本信息（脱敏）

- 渠道：实习信息平台｜岗位名「运营助理」｜标注日薪有明确区间
- 发现时机：投递并实际做了约 2 天后出现异常
- 证据图：含主体全称与收款信息，**仅留本机、不入库**（见同级 `附件/`，已被 gitignore）

## 异常是怎么发现的

1. 实际任务是**整理电商商品链接**等低门槛计件，与「运营助理」常规职责对不上。
2. 收款记录里的**付款方公司名**，与招聘页展示的公司名**不是同一主体**。
3. 到手金额明显低于岗位标注日薪下限（小额真实转账）。
4. 联网核验后：发薪方公开主营（如环保设备/材料）与「整理电商链接」**明显错配**，判高危/灰产。

## 联网核验结论（模式，非某家真名）

> 招聘展示主体｜**高危**｜发薪主体主营与任务不符｜发薪主体一致性：**不一致**｜业务与任务：**错配**｜风险点：主体不一致；整理商品链接属常见前置信任任务；先给小额真钱再升级｜建议：**排除**

## 提炼出的异常信号

1. **发薪/合同主体与招聘展示主体不一致** —— 比「企业信息不透明」更强的红线。
2. **业务与任务明显错配** —— 例如公开主业是环保/科技，实际却安排电商链接整理、刷单、点击任务。
3. **「整理商品链接 / 刷单 / 点击任务」本身是高风险关键词** —— 哪怕先给了真实小额报酬，也不能当作靠谱实习；常见套路是用小额转账建立信任，再诱导垫付或升级任务。
4. **到手报酬低于标注区间** —— 结算规则不透明。

以上已写入 [`配置/过滤规则.json`](../../配置/过滤规则.json) 的 `risk_flags`，并由企业核验 prompt 使用。

## 建议处理方式

- 立即停止继续投入时间。
- 不要在简历上写成正式实习经历。
- 警惕「升级任务」「需要垫付」「解冻资金」——一律终止，不要转账。
- 若已泄露证件或造成资金损失，保留聊天与转账记录，必要时通过 12315 或当地网警举报。

## 对本工具的价值

> 规则/核验提示词可识别主体不一致与业务错配 → 真实踩坑反向验证 → 把信号固化进过滤规则与核验脚本 → 后续批次自动拦截同类风险。
